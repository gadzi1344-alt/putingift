# ПутинGift: обновление для JonoGram

Это обновление существующего Worker, а не создание проекта заново. Оплата одной попытки — 100 XTR. Возможные призы, предварительно: 33% сердце, 33% кристалл, 33% шампанское и 1% NFT; все выдаются администратором вручную. До полного тестирования продажи должны оставаться выключены.

## 1. Получите настоящий адрес API

Адрес вроде `https://botapi.2-26-53-142.sslip.io` — лишь пример, пока администратор не подтвердит его. Попросите администратора открыть общедоступный HTTPS Bot API JonoGram с действительным TLS-сертификатом и сообщить точный корневой адрес без токена. Сервер JonoGram должен иметь возможность вызывать ваш HTTPS webhook на Cloudflare. Уточните поддержку setWebhook с secret_token, отправку заголовка X-Telegram-Bot-Api-Secret-Token и событий message, callback_query, pre_checkout_query.

Указанное пользователем описание оплаты XTR не проверено независимо. Не принимайте оплаты до полноценной проверки на настоящем сервере.

## 2. Перевыпустите токен

Старый токен попал в чат. Отзовите его через BotFather именно внутри JonoGram или попросите администратора. Новый никому не отправляйте; сохраните его в Cloudflare Workers → putingift → Settings → Variables and Secrets как Secret `BOT_TOKEN` и примените изменения.

## 3. Замените файл на GitHub

В своём репозитории откройте `index.mjs` → карандаш. Удалите старое содержимое, вставьте всё содержимое нового `index.mjs` из этого архива и сохраните через Commit changes. Можно вместо этого заменить файл загрузкой в корень репозитория. **Не заменяйте существующий `wrangler.toml` целиком**: в нём ваши ID базы и настройки.

Откройте `wrangler.toml` → карандаш. В секции `[vars]` добавьте:

```toml
BOT_API_BASE = "https://АДРЕС-ИЗ-АДМИНИСТРАЦИИ"
```

Замените пример на точный проверенный адрес JonoGram. Используйте только HTTPS, без токена, имени пользователя, пароля, параметров и якоря. Пример администратора вводите только после подтверждения и открытия API. Пока адрес не настроен, ни к какому Bot API запросы не отправляются. Сохраните и дождитесь успешного Deploy.

Проверьте, что `workers_dev = true` находится в начале файла до `[[d1_databases]]` и `[vars]`, а `PURCHASES_ENABLED = "false"` остаётся в `[vars]`. Там же укажите точный SUPPORT_USERNAME и реальные названия всех призов. Существующие database_id и настройки оставьте как есть.

## 4. Подключите webhook

В Secrets вашего Worker убедитесь, что есть `BOT_TOKEN` (новый, из JonoGram) и `WEBHOOK_SECRET` (случайный секрет: только буквы латинского алфавита, цифры, `_` или `-`, 1–256 символов). Временно создайте `SETUP_PASSWORD` как отдельную случайную строку длиной минимум 32 символа, сохраните и разверните.

Откройте `https://АДРЕС-ВАШЕГО-WORKER.workers.dev/setup`, введите SETUP_PASSWORD и подключите бота. После успешного подключения удалите SETUP_PASSWORD и разверните изменения. Страница настройки снова закроется. Используйте официальный workers.dev адрес, не пересылайте значения секретов. Если нет подключения, попросите администратора проверить доступность API и возможность исходящего HTTPS к Worker; чувствительные данные в логи или сообщения не вставляйте.

## 5. Проверьте и только потом включайте продажи

Откройте бота в JonoGram и проверьте `/start`, ручной ввод `/open` и inline-кнопку при выключенной продаже. Для полноценного теста выставления и оплаты счёта включите `PURCHASES_ENABLED = "true"` только в контролируемом тестовом окружении после подтверждения призов, готовности выдать их и наличия поддержки/возвратов; дождитесь redeploy. Выполните успешный тест 100 XTR с доверенным аккаунтом, проверьте ответ на pre_checkout, запись в D1, `/prizes`, ручную выдачу и возврат при необходимости. Автоматической выдачи и возврата нет.

На скриншотах и в сообщениях скрывайте токены, пароли и полные запросы к API (токен находится в URL запроса). Не публикуйте свой BOT_TOKEN на GitHub. Проверяйте допустимость платных случайных призов по правилам сервера и местному законодательству.
